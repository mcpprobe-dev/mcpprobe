## The 0.3.1 retune

The first registry survey (0.3.0) flagged META-01 on 83% of servers that listed tools, 63% at medium or above. On real descriptions from published servers the 0.3.0 rules raised medium or above on 2.8% of texts but on 22.5% of packages, because a server is flagged when any one of its tool, parameter or instruction texts matches, and the indicators that fired were ordinary documentation:

- `cross_tool_reference` at medium whenever a sibling tool was named in a text that also contained any of `when, before, after, always, never, prefer, instead...` ("call list_projects before this tool"), and at low for any mention at all, including tools named with dictionary words such as `search` matching ordinary prose;
- the `model directive` rule, which made usage guidance ("always use this tool to...", "you must call X first", "call this first when...") a medium finding on its own;
- `url` at low for every documentation link, `sensitive_path` at medium for any mention of `.env`, `mcp.json` or `~/.ssh` (including "paths such as ~/.ssh are rejected"), and `email_redirect` at high for `user@example.com` in parameter docs;
- server `initialize.instructions`, whose whole purpose is to steer the model, analysed exactly like a tool description.

0.3.1 keeps every high-specificity rule and changes those: usage guidance only counts alongside another instruction category; shadowing needs wording that changes what another tool does ("when send_email is used...", "do not use X", "X must route...", redirect/intercept/override); dictionary-word tool names count only when quoted; plain URLs and example.com addresses are not indicators; a credential path is medium only after a read/send verb and not negated; shadowing in server instructions is low. The demo's run_command and the 0.2.0 planted-instruction (`add` with `<IMPORTANT>` and `~/.ssh/id_rsa`) remain high.

## How to read this

- A text is *flagged* by the heuristics when META-01 raises an indicator at medium severity or above (first row) or at any severity (second row). Low-severity indicators (a credential path without a read/send verb, a URL next to send wording, a long description) are review prompts, not verdicts.
- The mcpprobe corpus is the one the heuristics were tuned on, so its numbers are in-sample and optimistic. The held-out set was written for this benchmark and not used for tuning; it is the better estimate, but it is small (60 texts) and written by the same project, so one miss moves recall by five points and it is not an independent sample.
- The real-benign sets are thousands of descriptions from published MCP server packages (official reference servers and vendor servers on npm and PyPI), all labelled benign, each analysed with its sibling tool names. Precision there is computed against all 31 poisoned texts of the two mcpprobe sets, so it depends on that mix; the FP rate is the base-rate-free number. The tuning split was used while retuning in 0.3.1; the held-out split comes from other packages, collected after the rules were frozen, and is the honest false-positive estimate. Recall is measured only on the project's 31 poisoned texts; there is no independent corpus of real poisoned MCP descriptions.
- The before/after table runs the 0.3.0 analyser (git ref shown) on the same samples.
- Hub prompt-injection datasets contain user prompts and jailbreaks, not tool descriptions, and include non-English text; META-01 is written for English tool metadata, so recall there is expected to be low and is a lower bound on domain transfer, not a measure of META-01 on MCP servers.
- No competitor publishes comparable detection rates; treat these as a regression baseline.
- The default Hub dataset is deepset/prompt-injections. Its licence was not verified when this script was written (the Hub page could not be fetched); it is recalled as Apache-2.0. Check the dataset card before relying on it.
